# Architecture

## Shared deterministic rulebook

The critical multiplayer invariant: *the same seed must produce the same
pieces and the same rules on client and server.* To guarantee this the rule
code is written twice — once in TypeScript, once in GDScript — as literal
mirrors:

| Rule | Server | Client |
|---|---|---|
| mulberry32 RNG | `src/game/rng.ts` | `src/core/rng.gd` |
| shape catalog + weights | `src/game/shapes.ts` | `src/core/block_shapes.gd` |
| board ops / line clears | `src/game/board.ts` | `src/core/board_state.gd` |
| scoring constants | `src/game/scoring.ts` | `src/config/scoring_config.gd` |
| set generator | `src/game/generator.ts` | `src/core/piece_generator.gd` |

`client/tests/run_tests.gd` embeds golden vectors generated by the TS code —
any drift between the two implementations fails the client tests.

## Server

```
src/index.ts          entrypoint, prints LAN addresses
src/config.ts         ports, durations, limits (env-overridable)
src/protocol.ts       message enum + payload types + validation helpers
src/net/wsServer.ts   ws lifecycle, JSON validation, rate limiting, routing
src/rooms/room.ts     lobby → countdown → playing → ended; reconnect grace
src/rooms/roomManager.ts  room codes, token index
src/match/matchSession.ts authoritative per-player board/score/cursor
src/game/*            deterministic rules (see table)
src/util/rateLimiter.ts
```

The server never trusts client-reported scores. `PLACE_PIECE` carries only
`(setIndex, slotIndex, cells)` — the server reconstructs the piece from the
seed, checks shape equality and board legality, applies clears, computes the
score, and relays compact bitmask updates.

## Client

```
main.gd / main.tscn   root: safe-area margin, screen fade-swapping, global
                      match-event routing, --smoke / --net-smoke test modes
src/config/           GameConfig (branding + SERVER HOST) + ScoringConfig
src/core/             rulebook mirror (pure logic, no nodes)
src/game/             GameController (board+score+set state), BoardView,
                      PieceView, TrayView, MiniBoardView, FxLayer
src/net/              Protocol (message constants), NetClient (WebSocketPeer),
                      MatchClient autoload "Net" (session/reconnect/state)
src/audio/            AudioMan autoload — all sounds synthesized at runtime
                      into AudioStreamWAV; Music/SFX/Master buses
src/util/             Settings autoload (ConfigFile persistence, identity,
                      token), Haptics
src/screens/          MainMenu, MultiplayerMenu (create/join lobby),
                      MatchScreen (gameplay), ResultsScreen, SettingsScreen,
                      DebugPanel
tests/                run_tests.gd (headless logic suite), net_smoke.gd
```

UI is built in code (no fragile .tscn wiring): every screen is a `Control`
script assembled in `_ready`. Rendering is custom `_draw()` with rounded
`StyleBoxFlat`s — zero binary art assets required.

### Drag & drop

Tray slot press → a `PieceView` ghost is spawned at *board cell scale*
(rendered cells = real board cells, so the preview maps 1:1), positioned
`DRAG_LIFT_PX` above the finger. `BoardView.pos_to_cell` derives the anchor
from the ghost's top-left corner; a translucent green/red preview follows.
Release on valid → snap tween + instant local commit + `PLACE_PIECE` to the
server. Release on invalid → spring return to the tray.

### Optimistic placement + server truth

The client applies placements immediately for zero-latency feel (same rules
→ same result). The server's `PLACE_ACCEPTED` carries the authoritative
score; `PLACE_REJECTED`+`BOARD_UPDATE` resyncs the board on any mismatch.
Opponent state (score, combo, 8×8 bitmask, connectivity) renders in a small
side panel.

## Deploying beyond LAN

The server is a plain WebSocket server — put it behind any TLS proxy
(Caddy/nginx/Render/Fly) and set `SERVER_HOST` + `USE_SSL=true` in
`game_config.gd` → `wss://your-domain`. Nothing else changes.
